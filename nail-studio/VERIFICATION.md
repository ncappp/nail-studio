PGlite использует последовательный адаптер одного соединения. Он не доказывает правильность межсоединительных блокировок. Для них добавлен отдельный test:postgres и PostgreSQL service в CI.

## Настоящий PostgreSQL в CI

npm run test:postgres требует TEST_DATABASE_URL на localhost с именем базы, заканчивающимся на _test, и отказывается перезаписывать существующую studio. Проверяются:

1. Восемь конкурентных созданий на одно время: один успех, семь конфликтов.
2. Отмена, уже стоящая перед worker в очереди advisory-блокировки: старое напоминание не отправляется.
3. Отправка уже началась: отмена ждёт её завершения, а другая запись создаётся параллельно.

Это PostgreSQL на отдельном тестовом контуре, не боевой Supabase. Актуальный результат удалённого прогона смотри в GitHub Actions для коммита PR.

## Ограничения

UI использует фикстуры Telegram/API; SQL-тесты не отправляют реальные сообщения. Работа webhook, реальная доставка, Storage upload и восстановление backups требуют отдельного тестового проекта и Telegram-аккаунтов. Чтение реального Supabase подтвердило приватные таблицы с RLS, настроенный works и активную минутную задачу nail-reminders; это не тест новых миграций на production.

На macOS headless Chromium запускается с --in-process-gpu. Можно указать CHROMIUM_PATH для установленного браузера. В Linux CI браузер устанавливается через Playwright. Тесты не содержат production-секретов.

## Воспроизведение

Из корня: npm ci, npm test, npm run build, npx playwright install chromium --only-shell, npm run test:ui. Для реального PostgreSQL — TEST_DATABASE_URL=postgresql://.../pearl_test npm run test:postgres на отдельной локальной базе.
