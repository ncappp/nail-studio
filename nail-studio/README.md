# Pearl · Telegram Mini App для маникюра

Версия 5: интерфейс исходного v4, сервер на Node.js/Vercel, PostgreSQL и Storage в Supabase, бот grammY. Это исходный проект для подключения и развёртывания, а не уже опубликованный сервис.

## Что работает в коде

- Клиентский путь: дата/время → подходящая по длительности услуга → имя и контакт (телефон или Telegram) → подтверждение.
- «Мои записи»: история, отмена и перенос с серверным ограничением 12 часов.
- Кабинет мастера: существующие пять вкладок, ручная запись, статусы, расходы, клиенты, настройки, фото.
- Проверка HMAC `initData` Telegram на сервере; срок сессии 1 час. При истечении нужно заново открыть Mini App.
- Мастер определяется только по `ADMIN_TELEGRAM_ID`; пустая переменная закрывает доступ всем. Кнопка или `#admin` не дают прав.
- Клиенту не передаются чужие имена, телефоны, заметки или расходы. Для календаря передаются только занятые интервалы.
- База общая для устройств. Экран обновляется каждые 30 секунд, когда нет открытой формы; при конфликте изменений админки предлагается повторить изменение.
- Цена и длительность берутся с сервера и фиксируются в записи; последующая правка услуги не меняет старые визиты.
- Запись защищена от повторного нажатия ключом запроса. Пересечения блокируются транзакцией и блокировкой строки студии.
- Уведомления мастеру и клиентке, напоминания за 24 и 2 часа, повторные попытки при временном сбое Telegram.
- Команды бота `/start`, `/appointments`, `/id`, кнопка Mini App.
- Фото преобразуются в JPEG и загружаются в Supabase Storage только через авторизованный серверный endpoint.

## Быстрый локальный запуск

Нужен Node.js 22 или 24.

```bash
npm ci
cp .env.example .env
# Заполни .env; не публикуй его.
npm run migrate
npm run dev
```

Сайт: `http://localhost:3000`. В обычном браузере ожидаемо появляется просьба открыть приложение через Telegram: обхода авторизации нет. Для работы с настоящим Telegram нужен доступный HTTPS адрес. Проверки без аккаунтов: `npm test`. Браузерные проверки: `npm run test:ui` (запускают локальный сервер и подменяют ответы API только внутри тестового браузера).

## 1. Supabase

1. Создай проект. В Connect скопируй строку **Transaction pooler** с портом `6543` в `DATABASE_URL` (учти URL-кодирование спецсимволов пароля).
2. Заполни `SUPABASE_URL` и серверный `SUPABASE_SERVICE_ROLE_KEY`. Они не должны попадать в клиентский JavaScript. Не отключай проверку TLS. Если среда не доверяет CA проекта, установи сертификат Supabase через `NODE_EXTRA_CA_CERTS`.
3. Запусти `npm run migrate`. Скрипт создаст приватную схему и начальную конфигурацию. Повторный запуск не стирает данные. Примерные услуги загружаются из `sql/catalog.json`; пустое расписание не позволяет клиентам записаться до настройки мастером.
4. Выполни `sql/002_storage.sql` в SQL Editor: создаётся публично читаемый bucket `works`, запись разрешена только серверному ключу. Не добавляй клиентские политики загрузки.
5. Демо-клиенты, прошлые визиты, вымышленные отзывы и рейтинг не импортируются. Встроенные фото помечены как примеры и заменяются после загрузки своих работ.

Хранение для одной студии: `private.studio` содержит JSONB-документ с услугами, расписанием, визитами, расходами и настройками. Все изменения выполняются в PostgreSQL-транзакциях под `SELECT FOR UPDATE`. Это осознанно простая схема для одного мастера; при росте до сети студий нужно разделить сущности и добавить `studio_id`. Таблицы `private.outbox` и `private.bot_updates` отдельные. Схема `private` не публикуется через Supabase Data API; RLS включён, клиентских политик нет.

## 2. Vercel

1. Положи содержимое проекта в свой Git-репозиторий и импортируй его в Vercel.
2. Framework Preset: **Other**, Build Command: `npm run build`, Output Directory: `public`, Install Command: `npm ci`.
3. Добавь серверные переменные из `.env.example` в Production Environment Variables:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Строка PostgreSQL transaction pooler |
| `SUPABASE_URL` | URL проекта Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ Storage |
| `BOT_TOKEN` | Токен существующего бота из BotFather |
| `ADMIN_TELEGRAM_ID` | Числовой Telegram ID мастера |
| `APP_URL` | `https://твой-проект.vercel.app` без завершающего `/` |
| `TELEGRAM_WEBHOOK_SECRET` | Случайная строка из букв, цифр, `_` и `-` |
| `CRON_SECRET` | Другая длинная случайная строка |

Секрет можно сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.

4. Выполни Deploy. После изменения переменных сделай Redeploy. Проверь `/api/index?action=health` — должен вернуть `{"ok":true}`. Это проверяет функцию, но не соединение с базой; проверка базы происходит при открытии приложения.
5. Production URL должен открываться без страницы Vercel Authentication. Webhook и cron не могут работать через интерактивный экран входа. Не подключай preview-деплой к боевому боту и базе.

## 3. Бот и доступ мастера

1. Скопируй Production значения `APP_URL`, `BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` в локальный `.env`.
2. Запусти `npm run bot:setup`. Команда регистрирует webhook, команды и кнопку меню. Она изменяет настройки существующего бота, поэтому выполняется только для выбранного тобой бота.
3. В Telegram отправь боту `/start`, затем `/id`. Поставь полученный ID в `ADMIN_TELEGRAM_ID` на Vercel и сделай Redeploy. Мастер должен начать чат с ботом, иначе Telegram может запретить ему уведомления.
4. В BotFather: `/mybots` → свой бот → Bot Settings → Configure Mini App / Main Mini App (названия пунктов могут отличаться). Укажи HTTPS URL проекта. Меню бота уже настроено скриптом.
5. Открой приложение кнопкой бота. Мастер увидит `admin`, остальные пользователи — только клиентские экраны.
6. В настройках задай название, адрес, часы, услуги, фото, шаблон времени и конец рабочего дня. По умолчанию `Europe/Samara` (UTC+4), конец дня 21:00. Пока есть будущие записи, изменение часового пояса запрещено, чтобы не сдвинуть визиты.
7. Во вкладке «Окошки» открой реальные даты и время. Окошко означает разрешённое **начало** визита. Продолжительность должна помещаться до конца дня и не пересекаться с другой записью. Отдельных интервалов перерывов пока нет: открывай начала так, чтобы нужная услуга не попадала на перерыв.

## 4. Напоминания

В проекте нет зависимости от минутного Vercel Cron. Используется Supabase Cron → защищённая HTTP-функция Vercel.

1. В Supabase включи расширения `pg_cron`, `pg_net` и Vault.
2. Через интерфейс Vault добавь `nail_app_url` = Production URL без `/` в конце и `nail_cron_secret` = тот же `CRON_SECRET`, что на Vercel.
3. Выполни `sql/003_reminders.sql`. Он вызывает `/api/index?action=cron` каждую минуту.
4. Проверь историю задач в Supabase Cron и ответы `net._http_response`. Не оставляй неработающий планировщик незамеченным.

Уведомления создаются в той же транзакции, что и запись. API пробует отправить подтверждения сразу; cron доставляет оставшуюся очередь. Напоминания планируются только если соответствующий момент ещё не прошёл. После переноса старые задачи отменяются и создаются новые; после отмены напоминаний нет. Опоздавшие больше чем на 30 минут напоминания не отправляются. У клиента должна быть возможность получать сообщения бота — проще всего начать с `/start`.

Доставка — at-least-once: редкий сбой после принятия сообщения Telegram, но до фиксации результата в БД, может привести к повтору. Telegram не предоставляет ключ идемпотентности для `sendMessage`. Ошибки `403` (бот заблокирован) прекращают повторы; временные ошибки повторяются с задержкой, максимум 10 попыток. Состояние доставки доступно в `private.outbox`.

## Проверка перед реальными клиентами

- Открой Mini App мастером и отдельным аккаунтом клиентки; проверь закрытый доступ к админке.
- На двух устройствах одновременно попробуй одну дату; одна запись должна сохраниться, вторая получить конфликт. Проверь также длинную услугу и соседнее время.
- Проверь подтверждение обоим участникам, перенос/отмену и изменение расписания после отмены.
- Проверь уведомления на настоящем Telegram и успешные задания Cron. Это нельзя подтвердить локальными тестами без твоих подключений.
- Загрузи собственное фото, обнови страницу, проверь отображение с другого устройства.
- Проверь стоимость/длительность всех услуг, часовой пояс, адрес и реальные свободные даты.

## Ограничения текущей версии

- Один мастер, один ресурс времени. Нет предоплаты, комбо услуг, листа ожидания, рассылок, новых отзывов с фото и Excel-экспорта: это следующий этап.
- Удалить запись можно только после отмены. Отметить «пришла»/«не пришла» можно после окончания услуги.
- Временное окно сеанса Telegram — 1 час; после него Mini App нужно открыть снова.
- Клиент может иметь до 5 будущих записей. Общие лимиты запросов для публичного URL можно дополнительно задать в Vercel Firewall.
- Удаление фото из галереи убирает ссылку, но пока не удаляет сам объект Storage. Ненужные объекты удаляются в Supabase вручную.
- Старая демо-база localStorage не импортируется автоматически. Настоящие данные, если они есть в прототипе, следует отдельно проверить и перенести.
- История визитов сейчас загружается целиком мастеру; для большой базы нужна пагинация и нормализованные таблицы.

## Обновление контактов

Одно поле «Телефон или Telegram» принимает номер, @username или ссылку t.me/username. Приложение нормализует контакт на сервере. Существующее поле данных `phone` сохранено для совместимости: теперь оно содержит номер или @username; авторизация и принадлежность записи по-прежнему определяются подписанным Telegram ID.

Кнопки связи открывают t.me-ссылки через Telegram WebApp API. Для записей с телефоном используется username аккаунта, полученный из подписанных данных Telegram, если он доступен; иначе предлагается поиск по телефону. Его результат зависит от настроек приватности Telegram. Для старых записей username автоматически не восстанавливается. При контакте Telegram без номера кнопка звонка скрывается.
